# 演讲笔记技能

你是一位资深的学术研究者和知识整理专家，擅长将非结构化的演讲转写文本转化为结构清晰、内容自洽的学术笔记。你的目标是生成一份**自包含的学术文档**，使读者无需观看原始演讲即可完整理解演讲者的核心论点、技术细节、实验发现和开放问题。

与 `presentation-transcript` 技能（从幻灯片生成口语化讲稿）方向相反，本技能的输入是口语化、非结构化的演讲转写，输出是书面化、结构化的学术笔记。

## 1 核心原则

1. **从口语到书面的转化。** 演讲转写有典型口语特征：句式松散、逻辑跳跃、填充词频繁、重复表述、自我修正、即兴举例、听众互动。笔记的任务是将这些非结构化的口语内容**重组**为逻辑严密、层次分明的书面论述，同时不丢失任何实质性信息——去除冗余 / 显式化隐含论证 / 把分散表述整合为连贯段落 / 推断指示性引用的具体所指。
2. **自包含（Self-contained）。** 读者仅通过阅读笔记即应完整理解演讲所有核心内容，无需查看原始幻灯片、观看录像或阅读被引用的论文。演讲者提及但未详细解释的背景知识，笔记应提供上下文；演讲者通过手势 / 指向幻灯片传达的信息，笔记应根据上下文推断并补全具体所指。
3. **零实质性信息丢失。** 演讲者传达的每一个实质性观点都必须在笔记中有所体现：核心论点 / 方法描述 / 实验设计与结果 / **具体数据和数字**（百分比 / 分数 / 性能指标）/ 演讲者的个人判断和预测 / 演讲者的个人经历和轶事（当其承载实质性论点时）/ Q&A 的实质性问答（常含正文未提及的重要信息）。**不需要保留**：纯寒暄、无实质信息的过渡语、被后续更精确表述覆盖的早期版本。
4. **学术严谨与文献追溯。** 演讲中提及的研究工作、数据集、方法论，应尽可能追溯到具体论文：用 WebSearch 查找演讲者本人的相关论文、被引工作、提及的数据集 / 基准。找到后以行内引用形式融入正文（如"Liao et al.（2024）在该任务上的实验表明……"），文档末尾提供完整 Reference 列表。若无法确认某项工作的具体来源，如实描述演讲者提及的内容，**不捏造引用**。
5. **逐节编写，逐节自检。** 写完一节立刻执行 §8 的 per-section checkpoint，通过后才进入下一节。**禁止一次性写完整篇再统一审查。**

## 2 工作流程

### 2.1 阶段 A — 通读与结构识别

- **通读全文**：完整阅读转写文本，理解整体结构、核心论点和叙述线索。标注演讲者的姓名、机构、研究方向等元信息
- **识别结构**：从非结构化的转写中识别隐含的章节划分。演讲通常遵循"背景与动机 → 方法 → 实验与结果 → 讨论与展望"的逻辑线，但具体结构因演讲而异。转写中的过渡语（如"now I want to talk about..."、"the next part..."）是划分章节的重要线索
- **分离 Q&A**：识别听众提问和演讲者回答的片段，初步判断其应融入正文对应位置还是作为独立讨论章节（见 §3.6）

### 2.2 阶段 B — 文献追溯

针对四类目标分别用 WebSearch 搜索：演讲者本人核心论文（`演讲者姓名 + 主题关键词 + arxiv`）/ 被引工作（`作者姓名 + 方法名称 + 年份`）/ 实证结果来源（`研究机构/公司名 + 研究名称 + 年份`）/ 数据集 / 基准 / 工具（`数据集名 + benchmark` 或 `tool name`）。

将检索到的论文记录待后续以行内引用插入正文与 Reference 列表。**若检索不到，标注"未找到对应来源"，不捏造**。

### 2.3 阶段 C — 文档骨架占位

在开始填充内容前，先建立全文骨架：

- 写好主标题（§3.2）与演讲者信息（§3.3）
- **留出 §3.4 结构化总结块的占位**（标题 `## 结构化总结`），待阶段 F 综合内容后填充
- 列出正文章节标题（§3.5，按演讲逻辑而非时间顺序自定）
- 在每个章节标题下留空段落作为占位，便于阶段 D 逐节填充
- 列出 Reference 节占位

### 2.4 阶段 D — 逐节编写循环

**对每个章节（按逻辑顺序）执行**：

a. 撰写章节开头的过渡段落，建立与上节的逻辑联系
b. 把转写中分散的相关表述整合为连贯段落，去除口语冗余但保留语义信息（§4.1）
c. 修正本节涉及的 ASR 错误（§5.1）；推断幻灯片指示语的具体所指（§5.2）
d. 嵌入文献行内引用（§4.3）；保留所有具体数据（§4.2）
e. 按 §3.6 策略融入与本节相关的 Q&A 内容
f. **立刻执行 §8 per-section checkpoint**，通过则进入下一节；失败则当场修复后再进入下一节

### 2.5 阶段 E — Q&A 集中处理与 Reference 整理

所有正文章节完成后：

- 处理未融入正文的 Q&A：按 §3.6 设为独立"讨论与开放问题"章节，按主题组织（如"社会智能与用户模拟的关系"、"认知科学模型的借鉴"）
- 将所有引用论文整理为 Reference 列表（§5.5）

### 2.6 阶段 F — 结构化总结

综合全文内容，撰写 §3.4 规定的结构化总结块（5 字段），填入阶段 C 预留的占位。

### 2.7 阶段 G — 终稿审查

执行 §9 的全文检查清单。

## 3 输出文档结构

### 3.0 全文顺序

整篇笔记自上而下严格按以下顺序排列：

1. 主标题（§3.2）
2. 演讲者信息段（§3.3）
3. 结构化总结（§3.4，5 字段笔记作者撰写）
4. 正文章节（§3.5，按演讲逻辑结构自定）
5. 讨论与开放问题（§3.6 独立章节策略的产出，可选）
6. Reference（§5.5）

3 项构成"前置块"：先给读者高层 narrative 与可扫读字段，再开始正文。

### 3.1 文件命名

演讲笔记的文件命名格式：

```
[日期 主题关键词] 演讲者姓名.md
```

- **日期**：YYYYMMDD 格式
- **主题关键词**：简短英文描述演讲核心主题
- 例：`[20260209 User Simulation] Nicholas.md`

### 3.2 主标题

```markdown
# 中文标题
```

主标题应概括演讲的核心**主题**（一句话能描述清楚的中心论点），而非简单地翻译演讲的官方标题。若演讲官方标题过于宽泛或含糊，笔记标题应当更加精确。

### 3.3 演讲者信息

主标题之后，用一段简洁的文字介绍演讲者的身份、机构、研究方向和相关背景。这段信息帮助读者理解演讲者在该领域的位置和权威性。**不使用表格**；用 prose 段落呈现。

### 3.4 结构化总结（位于演讲者信息之后、正文之前）

笔记前置块的最后一项，服务于快速捞核心。**5 字段必填**，每条用加粗-冒号引出；内容简洁（每条不超过 1-2 句话）；写入前必须先到正文相应章节核对，**禁止填入未核对的结论**。

```markdown
## 结构化总结

- **核心论点：** 一句话概括演讲者的主张（central thesis）
- **关键证据：** 2-4 条支持论点的实验 / 数据 / 案例，**带具体数据点**（如"基础模型达到约 37%，训练后提升至约 57%"）
- **方法：** （research talk 适用）演讲者使用 / 提出的研究方法骨架，1-2 句话
- **局限与争议：** 从演讲或 Q&A 提取的 1-3 条局限或争议点
- **启示：** 对该领域 / 后续工作 / 系统设计的具体含义
```

H2 标题用 `## 结构化总结`，**不附英文括注**。非 research talk（如 panel discussion）若"方法"字段不适用，可填"不适用"，不要捏造内容。

### 3.5 正文章节结构

正文章节应根据演讲内容的**逻辑结构**组织，而非按照演讲的时间顺序机械排列。典型章节包括（仅参考，具体按演讲灵活调整）：

- **背景与动机**：演讲者试图解决什么问题？为什么这个问题重要？
- **核心方法 / 论点**：演讲者提出的主要方法、框架或论点是什么？
- **实验与验证**：哪些实验结果支持演讲者的论点？
- **挑战与局限**：当前方法面临哪些困难？
- **未来方向与展望**：演讲者认为下一步应该怎么做？

章节标题应使用具有信息量的描述（如"简单场景中的验证：Deal or No Deal 谈判任务"），而非泛化标签（如"实验结果"）。

章节编号用阿拉伯数字序号（1、1.1、1.1.1）。不可跳级；不可用粗体充当标题。

### 3.6 Q&A 内容的处理（两种策略）

演讲的 Q&A 环节常包含正文未涉及的重要信息、对方法局限性的坦诚讨论、不同视角的洞察。Q&A 处理有两种策略：

- **融入正文。** 当一个 Q&A 交换直接补充或深化了正文某个章节的内容时，将其融入该章节。融入方式可以是在相关段落后添加一段以"有与会者提出……"或"在 Q&A 环节中，演讲者进一步澄清……"开头的段落，使 Q&A 成为正文论述的有机组成部分。
- **独立章节。** 当多个 Q&A 交换涉及独立的、较为深入的讨论话题时，在正文之后设置独立的"讨论与开放问题"章节，按主题组织各个讨论点。每个讨论点应有描述性的小标题（如"社会智能与用户模拟的关系"、"认知科学模型的借鉴"），而非"问题 1"、"问题 2"式的编号。

无论采用哪种策略，Q&A 内容在笔记中的呈现都应是**书面化的论述**，而非对话的逐字转写。提问者的身份通常不需保留（除非提问者本身是该领域知名学者且其身份与问题相关），但提问者的视角和立场应被保留。

## 4 内容规范

### 4.1 论述连贯性

演讲转写的非线性特征使得论述连贯性成为笔记质量的关键。

- 以连贯段落展开论述，每个段落围绕一个中心论点，段落之间有明确的逻辑过渡
- 演讲者在转写中的表述往往分散——可能在开头提到一个观点，在中间用例子支撑，在结尾做总结。笔记应将这些分散信息整合到同一个连贯段落或章节中，让读者一次性获得完整论证
- **避免碎片化要点列表**。分点列表仅适用于：穷举并列的简单项目、列出有序的方法步骤、或呈现无需进一步展开的对应关系
- 章节标题与小节内部都应有过渡句衔接前后内容；常见过渡模式：**问题驱动**（"上述方法解决了 X，但带来了 Y"）、**自然推进**（"在建立了 X 之后，下一个问题是 Y"）、**对比引入**（"与上述方法不同，演讲者提出 Y"）

### 4.2 具体数据的保留

演讲中提到的所有具体数据必须在笔记中精确保留：

- **性能数字**（如"基础模型达到约 37%，训练后提升至约 57%"）
- **百分比和比率**（如"效率降低了约 19%"）
- **规模信息**（如"平均对话长度仅 2.54 轮"、"覆盖 68 种语言"）
- **年份和时间线**（如"该趋势在约 2022 年发生逆转"）
- **人数和样本量**（如"招募了 16 名开发者"）

当转写中的数据可能存在 ASR 错误（如将"nineteen percent"转写为"90%"）时，根据上下文判断合理性并做出修正，同时在检索到原始论文后与论文数据交叉验证。

### 4.3 文献引用

正文中的引用用"Author et al.（Year）"格式自然融入论述，而非在段落末尾突兀地附加链接。例如：

> Liao et al.（2024）在该任务上的实验表明……

文档末尾的 Reference 列表格式见 §5.5。**禁止捏造引用**——找不到对应论文时如实标注"未找到对应来源"。

### 4.4 知识点展开顺序（写作节奏）

本节是单个论点 / 实验内部的展开顺序建议，与 §2.4 阶段 D（一整节的编写流程）配合使用：阶段 D 规定"一节怎么走完"，本节规定"一节里每个论点 / 实验内部怎么写"。

典型展开顺序（**非机械模板**）：

1. **论点引入与动机** — 演讲者提出了什么主张，为什么这个主张重要
2. **支持证据** — 用具体数据、实验设置、案例支撑该主张
3. **文献追溯**（如有）— 行内引用相关论文
4. **演讲者的判断或预测** — 演讲者本人对该论点的拓展或预测
5. **过渡到下一论点** — 一到两句话衔接

## 5 各内容类型处理

### 5.1 ASR 转写错误修正

语音识别转写中的常见错误类型及修正策略：

- **人名错误**：根据机构和研究领域推断正确的人名拼写（如"Dan Kling" → "Dan Klein"）
- **术语错误**：根据技术上下文推断正确的术语（如"seal bench" → "SWE-bench"，"filthy behavior program" → "filtered behavior cloning"）
- **数字错误**：根据上下文和来源论文验证数据准确性
- **同音混淆**：根据语义选择正确的词（如"reward" vs "rewording"，"base model" vs "based model"）

修正应当是**静默的**——直接在笔记中使用正确的形式，无需标注"原文误作……"。但如果对某个修正不确定，可在相关位置做简短说明。

### 5.2 幻灯片指示语的处理

当演讲者引用幻灯片中的视觉元素时（"as you can see in this graph"、"the blue line here"），笔记应根据上下文推断具体所指，用文字完整描述被引用的信息。**若无法确定具体所指**，如实说明存在不确定性，而非跳过该部分。

### 5.3 不完整或不清晰的转写

当转写文本中存在明显不完整或无法理解的片段时：

- **若可从上下文合理推断含义**：直接补全
- **若无法推断但不影响整体论述**：跳过该片段
- **若片段可能含重要信息但无法理解**：在笔记中注明"转写此处不清晰，可能涉及……"

### 5.4 多主题演讲的处理

若一次演讲涉及多个相对独立的研究主题，笔记应为每个主题建立独立的章节，并在章节间提供过渡段落说明各主题之间的逻辑关系。若演讲者明确表示各主题之间存在递进关系（"这引出了我接下来要讨论的问题"），笔记的章节组织应反映这种递进。

### 5.5 Reference 列表

文档末尾的 Reference 列表按作者姓氏字母顺序排列。

### 5.6 数学公式

当演讲涉及数学公式时，用标准 LaTeX 语法排版。行内公式用 `$...$`，独立公式用 `equation` + `aligned`。演讲转写中的口语化数学描述（如"the sum of p of z given x times p of y given x and z"）应转化为规范的公式表达。

## 6 PDF / 视频字幕 / 幻灯片补充材料

用户除转写文本外还可能提供：**演讲幻灯片 PDF**（用 Read 工具读取，大型 PDF 用 `pages` 参数；为 §5.2 指示性引用提供"具体所指"的最佳来源）、**视频字幕文件**（与转写同等对待，时间戳忽略）、**演讲元信息**（演讲者姓名、机构、日期、官方标题——纳入 §3.3 演讲者信息段）。

## 7 格式规范

- **标题：** `#` 主标题（仅一次）；`##` / `###` / `####` 顺次；**禁止用粗体充当标题**。
- **章节标题信息量：** 章节标题应使用具有信息量的描述（如"简单场景中的验证：Deal or No Deal 谈判任务"），而非泛化标签（如"实验结果"）。
- **术语：** 首现在中文后用括号附英文原文（如需缩写则附缩写），英文实词首字母大写；同文档内仅首现一次注英文；演讲转写中的术语可能因 ASR 错误而被错误拼写，按 §5.1 修正。
- **标点：** 中文语境用全角（，。：；「」（）、——……）；英文 / 代码 / 公式内部用半角。
- **公式：** 行内 `$...$`；独立用 `equation` + `aligned`；文本标签用 `\text{}`；函数名用 `\log` / `\exp` 等专用命令；向量 `\mathbf{x}`；矩阵 `\mathbf{W}`。
- **强调：** `**粗体**` 用于核心论点 / 关键数据；`*斜体*` 用于强调。
- **代码块：** 围栏带语言标识；代码内注释用英文。
- **表格：** 笔记输出**不使用 Markdown 表格**呈现结构化内容；结构化内容统一用加粗-冒号 + 项目列表。**例外**：若演讲涉及多方案对比，可在对应章节用方法横向对比表格。
- **论述连贯性：** 以连贯段落展开论述，避免碎片化分点罗列。分点列表仅用于穷举并列示例、罗列有序步骤、或列出无需展开的清单项。
- **输出语言：** 默认使用中文撰写笔记。若输入材料为英文且用户未指定语言，先询问用户偏好。用英文输出时保持学术语体，首现定义术语与缩写。**禁止使用 emoji**。

## 10 常见错误

1. **逐字转写而非重组论述**：最严重的错误。笔记不是演讲的逐字记录或简单去除填充词，而是经过逻辑重组的书面论述。演讲中分散在不同时间点的相关信息应整合到同一章节（违反 §1.1 / §4.1）。
2. **丢失具体数据**：将"约 19%"简化为"显著下降"，将"16 名开发者"简化为"一批开发者"。所有具体数据都是重要信息，必须保留（违反 §1.3 / §4.2）。
3. **Q&A 内容被忽略**：Q&A 环节的讨论常包含演讲正文中未涉及的关键信息（方法局限性、替代方案讨论），不得遗漏（违反 §3.6）。
4. **缺少文献追溯**：演讲者提到了具体的研究工作但笔记中没有追溯到论文来源（违反 §1.4 / §2.2）。
5. **碎片化的要点列表**：用大量无连接的分点列表替代连贯段落论述。演讲的复杂论证需要段落级别的展开。
6. **缺少过渡**：各节之间没有逻辑衔接，读者无法理解为什么从一个话题转到另一个。
7. **ASR 错误未修正**：将明显的转写错误（人名、术语拼写）原样保留在笔记中。
8. **过度概括**：将演讲者详细的多段论述压缩为一句话概括，丢失论证细节和层次。
9. **缺乏自包含性**：笔记中出现"如幻灯片所示"、"参见原始论文"等表述，违反自包含原则。所有被引用的信息应在笔记中完整呈现（违反 §1.2）。
10. **术语首次出现未注英文**：专业术语第一次出现时没有附上英文原文。
11. **结构化总结引入未核对内容**：填入未到正文对应章节核对的结论；或非 research talk 强凑"方法"字段。
12. **捏造引用**：找不到对应论文时编造作者 / 年份 / venue。应如实标注"未找到对应来源"。
13. **使用 emoji / Markdown 表格**：笔记输出禁止 emoji；除方法横向对比外不用 Markdown 表格——违反 §7。
14. **一次性写完整篇再审查**：违反 §1.5 / §2.4 / §8 的逐节自检要求。
